## 3. Concepts in own words

Locked: own-words paraphrase no code block.

Locked: shapes only no tunables copied.

Arrival in own words: a waking task is first considered for immediate
local placement near where it woke. Tasks tied to graphics locality,
sticky event heavy behavior, or a recent idle target are favored for
that fast local path so they can run without waiting behind the shared
backlog. When no suitable idle target is present the task falls through
to a shared queue and, where needed, a distant idle helper is nudged to
help empty the backlog. The fast path carries its own wakeup effect so
no second nudge is needed when it succeeds.

Ops in own words: the observed hook set covers a placement hook at
wakeup, a queueing hook, a per cpu draining hook, a periodic tick hook,
a wakeup notice hook, a start hook, a stop hook, an enable hook, a task
init hook, a task exit hook, plus scheduler init and exit hooks. The
placement hook decides between direct local handoff and fallthrough.
The queueing hook decides between local handoff and shared queue entry.
The draining hook moves ready work to the local queue. The tick hook
can force a reschedule when a slice is exceeded. The wakeup notice hook
tracks sleep gaps and pace. The start hook snapshots run time and
advances a global ordering floor. The stop hook accounts used time and
updates load and frequency state. Enable plus init plus exit hooks cover
task lifecycle and scheduler startup and teardown.

Ordering in own words: the shared queue is ordered by a per task
deadline that builds on prior virtual time plus scaled execution since
the last sleep. Frequent sleepers keep a bounded credit so interactive
tasks can sit ahead of long runners without accumulating unbounded
advantage. The credit bound grows with sleep frequency and shrinks for
steady runners. Slice length scales with task weight and is further
adjusted for cpu capacity, so heavier tasks receive shorter deadlines
and lighter tasks receive longer ones in a smooth proportional sense.
A global floor tracks the newest seen deadline so late joiners do not
enter far in the past.

Dispatch in own words: each cpu first tries to move one ready task from
its shared queue to its local queue. When the shared queue has nothing
runnable here the cpu refreshes a per node empty stamp used for backlog
detection. When the prior task still has slice left and no other waiter
wants this cpu, the prior task is allowed to continue on primary domains
rather than migrating. Local handoffs outrank the shared order by
design so pinned or strictly local work never waits behind the shared
backlog.

Drain in own words: backlog is judged by sustained presence, not by a
single instant of emptiness. An empty stamp per node records the last
time the shared queue was seen empty, and only a backlog that persists
across a window counts as saturated. While saturated, idle helpers
outside the primary domain are nudged to wake and help empty the
backlog. The nudge is batched and deferred where possible to avoid
ping pong on transient emptiness. Direct local handoffs skip this path
since they never entered the shared backlog.

Kick and idle in own words: idle search prefers the prior cpu first,
then a fully idle core sharing the same hardware thread pair, then any
idle cpu in the primary domain, then any idle cpu system wide. Busy
tracking from recent user time decides when a light scan is enough and
when a fuller scan is warranted. Contention is sensed by checking
whether the sibling thread is busy while other idle cpus remain, which
steers placement toward full cores under load and toward locality when
quiet. Wakeups for shared queue entries nudge an idle target, while
direct local handoffs need no extra nudge. Capacity differences across
cpus scale the accounted time so slower cpus are not mistaken for idle.

## 5. Seven point lag checklist vs stress-ng style load

Locked: seven areas paraphrased no copy.

Locked: each area maps to open hypotheses with TBD kept.

This section asks, for each of seven areas, whether flow may handle the
shape the wrong way somewhere that could show as lag under a dense burn
plus probe load. Each item paraphrases the cosmos shape versus the
5.0.16 flow shape in own words, then flags a delta as a hypothesis
mapping. No item claims a root cause and no item proposes a code change.
All mappings stay TBD with proof open.

C1 smoothing wrong way: flow keeps a smoothed frequency hint that blends
mostly prior with a small fresh share using integer floor, keeps a short
shadow ring for post mortem only, and stays neutral for placement with
the hint feeding only the governor path, while the burn score uses the
same blend shape with separate growth and decay counts on its own cpu.
The learned shape instead tracks wakeup pace with a capped moving
average plus periodic busyness evals that gate which scan path is used.
Delta: flow smoothing never steers placement while the learned shape
lets recent pace and busyness steer scan choice, which may leave flow
slow to notice a shift from quiet to saturated. Maps to H2 plus H7,
both TBD.

C2 deadline or virtual time wrong way: flow orders by lowest boosted
virtual time with ties to strand A, keeps charges saturated at max with
no wrap, scales base charge by weight while extra quanta stay uniform,
and pushes postponed work behind the sequence floor plus overrun debt
scaled to the award. The learned shape orders a shared queue by per task
deadline built from prior virtual time plus scaled execution since last
sleep, with bounded sleep credit that grows for frequent sleepers and a
global floor that stops late joiners entering far in the past. Delta:
flow debt is uniform per award while the learned deadline credit is
paced by sleep frequency, which may leave flow either too kind or too
harsh to bursty interactive tasks under saturation. Maps to H3 plus H4,
both TBD.

C3 kick or preempt wrong way: flow uses a constrained kick that compares
boosted keys on both sides with a frozen gap plus tail, counts a win
only on preempt, keeps a fast path for pinned local wakes that skips the
gap check, and adds a streak cover that turns an idle wake into a
preempt at the bound. The learned shape carries wakeup inside direct
local handoff with no extra nudge, batches and defers shared queue
nudges through a timer, and only nudges distant idle helpers when
backlog persists. Delta: flow kicks eagerly per enqueue with a gap test
while the learned shape defers and batches, which may leave flow with
extra wakeup cost or missed coalescing under dense wakes. Maps to H6
plus H7, both TBD.

C4 sorting tasks wrong way: flow pops pairs by lowest boosted key with
ties to strand A and first in first out within a class, then spills to
the LLC queue on miss, with bounded retries and caps on walks. The
learned shape lets any direct local handoff outrank the whole shared
deadline order and otherwise takes the earliest deadline from the shared
queue. Delta: flow sorting is always global by boosted key while the
learned shape lets locality outrank deadline when quiet, which may leave
flow migrating more than needed when quiet and draining less promptly
when saturated. Maps to H1 plus H5, both TBD.

C5 enqueue or dispatching wrong way: flow enqueue stamps wait start with
no virtual time shift, gives latency tasks a one shot offset of one
slice with no accumulation, carries remain for requeues with a weight
scaled charge else steps fresh time past the sequence with a unique
floor, and dispatch pops with bounded retries plus fallback plus forward
handling. The learned shape decides at wakeup between direct local
handoff and fallthrough, inserts to shared order by deadline at
queueing time, and drains per cpu by moving one ready entry from shared
to local with keep running on primary when no waiter wants the cpu.
Delta: flow separates placement at enqueue from draining at dispatch
with pair then LLC spill while the learned shape decides placement
earlier and drains with continuity, which may leave flow with extra hops
under contention. Maps to H1 plus H5, both TBD.

C6 reclaim wrong way: flow reclaims idle time with hierarchical steal as
a bounded push pull analogue, keeps steal counts split by pair plus LLC,
forwards the head when the thief cannot run it with outcome split into
preempt plus idle plus skip, and never loses work on no valid owner. The
learned shape has no thief path in the same sense and instead nudges
idle helpers outside the primary domain to wake and help empty a
sustained backlog. Delta: flow pulls work to idle cpus while the learned
shape pushes wakeups to idle helpers only on sustained backlog, which may
leave flow either too eager or too idle under uneven backlog. Maps to H6
plus H8, both TBD.

C7 what else may cause lag: beyond the six shapes above, flow holds an
awarded run for one slice times q with no weight scale on the extra
part, scores fresh cpus at zero with q one until the first count, gives
voluntary plus empty waits decay precedence with separate counts, steps
the hold only on the stop edge with one add per epoch, treats frequency
as neutral for placement, and needs restart for hotplug plus reinstall.
The learned shape favors very short slices with deferred batched wakeups,
capacity scaled accounting so slower cpus are not mistaken for idle,
node aware placement with primary domain preference, and optional
graphics locality hints bounded to a safe workload boundary. Delta:
extended holds plus neutral frequency plus restart only topology may
interact under a stress-ng style burn to hold the head, miss pace
shifts, or sit on a stale topology. Maps to H4 plus H8, both TBD.
