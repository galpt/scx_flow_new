# 5.1.0 Strict PRIQ

Status: design record for the 5.1.0 build. Base: 5d7be59 with a clean
tree. This note lands with its code, and the code matches this note.
Any number not listed here stays as in 5.0.16. No live migration
follows from the install: reinstall needs a restart with no live
transition. No push without approval.

This note uses plain prose. It states fixed numbers and fixed rules.

## 1. Base and scope

The base is 5d7be59 with a clean tree. The scope is one scheduler
build plus docs plus version sync. The scheduler drops the pair
queue layer and queues directly on kernel dispatch queues. Later
sections define the exact shape. The prior release behavior stays
except the queue topology plus the tie rule plus the stats layout
defined below.

## 2. Problem of DHQ cost against kernel PRIQ

The pair layer costs an arena, per pair heaps, capacity sizing, a
static area, occupancy gauges, stale handling, and two level drain
walks, all to order tasks that the kernel already orders. Each
per LLC queue already carries virtual time order with equal times
leaving in insertion order. The pair layer repeats that order at
higher cost and wider verifier surface. The fix queues directly on
the per LLC queues and keeps one fallback queue, with a per LLC
monotonic floor keeping fresh times unique. The kernel order is
the only order.

## 3. Topology of per LLC PRIQ plus fallback with no pairs

One queue per LLC plus one fallback queue. The queue id is the base
plus the LLC index. The fallback id is fixed. Init creates each
queue and records one node index per LLC for drain order. No pair
queue is created, no static area is sized, no capacity is stored,
no strand is assigned. Hotplug needs a restart since tables are
seeded once.

## 4. Ordering of strict PRIQ with FIFO ties

Each queue leaves in virtual time order with equal times leaving
in insertion order. The kernel keeps that order, so the scheduler
holds no tie code. Stored time stays raw while latency tasks take
a one slice queue key shift applied once per enqueue. The old tie
to a fixed strand is retired with the pair layer.

## 5. Enqueue by insert time on LLC or fallback with pinned FIFO

The constrained target picks the queue: the hint when allowed and
live, else the first allowed live CPU, else the fallback queue.
Shared tasks join by virtual time with a slice of one quantum
times the award. Pinned tasks join the local queue of the allowed
CPU by plain insert in FIFO order with one slice, no award, no
penalty, and no latency shift. Exiting tasks take the local queue
when allowed with a minimal slice, else the LLC queue. The queued
flag drops a second enqueue of the same task. One kick per enqueue
keeps wakes bounded.

## 6. Dispatch as ordered drain to local

Each CPU drains its own LLC queue first, then LLC queues on the
same node, then LLC queues on other nodes, then the fallback
queue. Each step peeks once: a head that cannot run here forwards
one wake to the owner with no move, else the head moves to the
local queue. Remote moves count steal on the thief and drop the
queued gauge on the victim. The fallback move takes a best effort
drop from a victim with backlog.

## 7. Kick of constrained compare plus pinned fast path

The constrained kick preempts when the running time leads the
waiter key by at least the threshold with slice past the tail,
else it wakes idle. Both sides compare latency shifted keys, so
latency wins ties by one slice. The pinned kick preempts past the
tail with no gap check, since a pinned wait cannot run elsewhere.
A streak at or above the bound turns an idle wake into a preempt
with an escape count. Missing, disallowed, or offline targets
count a skip with no wake. The mask is revalidated before each
wake.

## 8. Hog control of award debt plus streak plus escape

A full burn postpones the task by the award length with
saturation at the maximum and no wrap: one uniform slice plus one
per extra quantum, so a three quantum burn pays three slices. The
base charge scales by weight while the extra stays uniform, so a
heavy task pays a large relative step and a light task already
sits behind on its base charge. The streak steps by the award on
the stop edge only with one add per run, capped at twice the
bound, decaying one step on a clean stop and clearing on a pinned
start. An old wait steps the hold down one with a rescue count.
The bound fires the escape preempt. Fresh reads zero with one
quantum until the first count. Voluntary stops and empty waits
decay. Only a full awarded burn with a top raw step grows. All
adds saturate, so long burns at the ceiling keep counting with
the time held at the maximum.

## 9. Cgroup plus frequency plus lifecycle plus stats

Cgroup weight shares keep the 1 through 10000 range with default
100. Enqueue reads the live map by id with a miss reading as
default. Move and init seed a hint only. Frequency blends three
parts prior with one part fresh for the governor only and never
steers placement. Lifecycle keeps init, enable, running,
stopping, tick, dequeue, select, mask change, exit, and the
cgroup hooks with single ownership through the queued flag.
Stats keep twenty one counters in struct order at 168 bytes with
total meeting penalty plus extra on each award and on deltas. The
pair only counters are gone with the pair layer.

## 11. Invariants

Fixed numbers only with no tunable. All verifier programs pass
with stacks at or below five hundred twelve bytes and bounded
loops over LLCs only. Order is kernel virtual time with FIFO
ties. Stats follow the struct order above. Hotplug plus
reinstall need a restart with no live transition. Sources stay
in own words with no copied text and no code block. Single
ownership holds through the queued flag with no loss.

## 12. Failure modes plus rollback

A bad queue id falls back to the fallback queue. A missing task
context queues raw with an idle wake only. A duplicate requeue
drops with a count. An invalid cached LLC falls back to zero. A
mask change between pick and kick never wakes off mask. Init
refuses over bound counts before any queue use. Rollback keeps
the prior 5.0.14 snapshot: reinstall that binary with a restart.

## 14. Questions Q1 through Q10

Q1 topology: each LLC owns one queue plus one fallback with no
pair queue created. Proof reads the init return plus the queue
creation counts on a workspace build.

Q2 ordering: queues leave in virtual time order with FIFO ties
from the kernel. Proof runs two tasks at equal time on a live
soak and reads FIFO leave order from the probe log.

Q3 enqueue: shared tasks join by time with slice times award,
pinned tasks join local FIFO with one slice. Proof reads insert
slices plus queue ids from the per award log on the same run.

Q4 dispatch: own LLC first, then same node, then remote, then
fallback, with forwards for unrunnable heads. Proof reads steal
plus forward growth with backlog on remote LLCs on the same run.

Q5 kick: gap plus tail preempts, pinned fast path preempts past
the tail, streak preempts at the bound. Proof reads preempt plus
idle plus skip plus escape on the same run with pinned waits
present.

Q6 hog debt: a full burn postpones by the award length with
saturation. Proof reads overrun plus penalty one to one with
extra plus total matching the award on the same run.

Q7 streak: steps by award on the stop edge only with one add per
run, decay on clean stops, clear on pinned starts, rescue on old
waits. Proof reads escape growth to zero stuck holds with mixed
burn plus yield load on the same run.

Q8 score: fresh zero with one quantum, growth only on full burns
with top raw steps, decay elsewhere with separate counts. Proof
reads growth plus decay counts with old plus new plus path on the
same run.

Q9 stats: twenty one counters in order with total meeting penalty
plus extra per award and on deltas. Proof runs the books check
on interval windows from the harness summary.

Q10 soak: strict X plus Y plus Z together on the same one hundred
twenty second full burn plus probe run with at least three
repeats each for probe plus control.
